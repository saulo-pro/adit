adit — several WireGuard tunnels, at once

An open-source client for WireGuard® tunnels on macOS that keeps several of them up at once, with a menu bar icon and a command line that do the same things.

Why it exists

The official WireGuard app for macOS keeps one tunnel up at a time and has no command line. wg-quick runs several, but asks for the administrator password on every use and does not come back after a reboot. adit covers both.

What it does

Several tunnels at once

Each routes only its own networks. A tunnel whose networks or DNS domain overlap one that is up, adit's or another program's, is refused before it connects, with the reason.

A full tunnel beside them

AllowedIPs = 0.0.0.0/0 takes everything but the local network and the other tunnels, which keep their networks and DNS. Every tunnel's server stays outside it, and IPv6 is blocked if it carries only IPv4.

A kill switch

On by default: while the full tunnel is coming up or has dropped, nothing leaves the Mac around it. always blocks even while it is down; adit signin lifts it for a hotel's sign-in page.

Which tunnel carries this?

adit route git.corp.example names the tunnel an address or a name goes through, and the DNS server that looks it up.

Menu bar and command line, one state

Both talk to one privileged service, aditd, so a tunnel switched in one flips in the other at once.

JSON for scripts and agents

Every command answers in plain words, or in JSON with --json, with exit codes that mean something.

Back after a reboot

The tunnels you choose come up at boot, before anyone logs in, and follow network changes.

No password for daily use

The administrator password is asked once, at install. Switching tunnels needs none.

DNS per tunnel

DNS = 10.99.1.1, corp.example sends names under corp.example to 10.99.1.1 and leaves every other name alone, or to the full tunnel's servers.

Honest status

The last handshake and the bytes each way, not just “connected”.

Plain .conf files

The same WireGuard files wg-quick and the official apps read, in and out. No lock-in.

Other tunnels, read-only

The WireGuard app's and wg-quick's tunnels are shown, with wg-quick's handshakes and counters. adit never changes them.

Install

With Homebrew:

brew install saulo-pro/tap/adit
sudo adit install

Or with one line, without Homebrew:

curl -fsSL https://adit.saulo.pro/install.sh | sh

It downloads the latest release from GitHub, checks it against the release's SHA256SUMS, puts adit, aditd and adit-tray in /usr/local/bin and runs sudo adit install; sudo asks for your password once. Read it first if you like. Run it again to upgrade. It stops on a Mac where Homebrew installed adit, since the two copies would replace each other. To remove what it installed: sudo adit uninstall, then delete the three binaries from /usr/local/bin.

sudo adit install copies aditd to /Library/PrivilegedHelperTools/pro.saulo.adit, where only root can change it, and starts it now and at every boot. It also sets the menu bar icon to start at every login, from its own root-owned copy, and creates the adit group with you in it. Run it again after every brew upgrade adit.

Use

sudo adit import work.conf     # add a tunnel; hook lines are kept but never run
adit up work                   # no password
adit status                    # every tunnel, adit's and other software's
adit status work --json
adit autostart work on         # bring it up at boot
adit route git.corp.example    # which tunnel carries it, and who looks it up
sudo adit dns work corp.example   # send names under corp.example to work's DNS servers
adit down work

sudo adit import home.conf     # a full tunnel: AllowedIPs = 0.0.0.0/0 and a DNS server
adit up home                   # everything goes through it, beside work
sudo adit killswitch home always   # on-drop (default), always or off
sudo adit lan home block       # allow (default) or block the local network
adit signin                    # lift the kill switch for 2 minutes: hotel sign-in pages
sudo adit export work --output work.conf   # a new file, readable only by you
sudo adit remove work
sudo adit allow caroline         # let another account switch tunnels
sudo adit uninstall            # removes aditd, the group and every tunnel with its keys

Exit codes: 0 done; 1 failed, with the reason; 2 wrong usage; 3 aditd not reachable; 4 not allowed; 5 no such tunnel; 6 refused because of a conflict.

Security

  • aditd runs as root and only does tunnel work. It answers on a Unix socket that belongs to root:adit with mode 0660, and also asks the kernel who each caller is. Members of the adit group may list, switch and watch tunnels. Adding, removing and exporting tunnels needs sudo, so a program running as you cannot slip in a tunnel or read the keys.
  • aditd never runs a command or opens a path it was sent. Hook lines (PreUp, PostUp, PreDown, PostDown) are kept, so an export gives the file back unchanged, and never run.
  • Private keys stay in /var/db/adit, which only root can read, and never appear in output, logs or the menu. Export writes a new file only, readable only by you.
  • No telemetry, and no network traffic but the tunnels' own.

How it is built

PartWhat it does
aditdThe root service, started at boot by a LaunchDaemon. It runs each tunnel with wireguard-go on its own utun interface and sets addresses and routes the way wg-quick does. A full tunnel's kill switch is a pf anchor of its own, which outlives aditd.
aditThe command line, a client of aditd's socket.
Menu bar iconAnother client of the same socket.
